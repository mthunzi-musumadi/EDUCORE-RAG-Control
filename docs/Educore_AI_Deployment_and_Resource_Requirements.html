1. Grounding in the Actual Framework (EDUCORE_AI_FRAMEWORK)

This technical analysis directly references the official governance corpus maintained in EDUCORE_AI_FRAMEWORK, consisting of the Master Governing Handbook (EDU-AIMS-HBK-v1.0/v2.0), the Central Organizational Policy (EDU-AIMS-POL-v1.0/v3.0), the 180-Day Implementation Action Plan (EDU-AIMS-PLN), and the Academic Cognitive Bypass Audit Checklist (EDU-AIMS-CHK).

1.1 Dual-Track Organizational Charter

The Educore AI Management System (AIMS) governs two strictly differentiated institutional tracks:

  • Track 1: Enterprise Business Operations — Governs Finance, Procurement, IT/DevOps, Human Resources, Legal, Facilities, and Central Administration. Focuses on data loss prevention, financial verification, secret scanning, and Zambian statutory data residency.
  • Track 2: Academic & Pedagogical Transformation — Governs Teaching Faculty, Curriculum Heads, Teacher Academies, and Students across Sentinel Kabitaka (SKAB S, SKAB P), Sentinel Kalumbila (SKAL), Trident College (TCL), Trident Preps (TPS, TPK, TPL), and Frontier Nkisu. Focuses on Cambridge 0580 syllabus alignment, human-in-the-loop review, Adelaide-model intellectual ownership declarations, and Viva Voce oral defenses.

1.3 8 Departmental Non-Software Guardrails

The backend enforces procedural stop-conditions that software firewalls cannot intercept:

  • Fin-01 (Dual-Key Manual Audit): Independent human calculation audit notice appended to all AI-generated financial amounts.
  • Fin-02 (Zambian DPIA Compliance): Regex redaction of Zambian National Registration Card (NRC) numbers (\b\d{6}/\d{2}/\d{1}\b) and FQM mining partner subsidies.
  • IT-01 (Pre-Commit Secret Scanning): Automated detection and blocking of AWS credentials, RSA private keys, and database connection URIs in user prompts.
  • HR-01 (Algorithmic Autonomy): Absolute prohibition on automated candidate shortlisting, rejection, or appraisal scoring.
  • Edu-01 & Edu-02 (Curriculum Verification): Prohibition of automated summative exam grading; mandatory alignment against Cambridge 0580 syllabi.
  • Stu-01 (Cognitive Bypass Prevention): Diagnostic hints only for students; homework answer dumping is strictly blocked.
  • Fac-01 & Fac-02 (Physical Safety): Ban on campus gate facial recognition/emotion tracking; instant human emergency dispatch for hazards.
  • Leg-01 & Leg-02 (Legal Accountability): Statutory verification against Zambian law books; non-delegable executive accountability.

2. Prototype Limitations vs. Production Concurrency

The current repository implementation in src/backend/educore_enterprise_backend.py serves as an operational proof-of-concept. To support 2,500 concurrent active users and 5,000 registered accounts, several core bottlenecks must be transitioned:

Subsystem Current Prototype State Failure Mode under 2,500 Concurrent Users Target Production Replacement
Web Listener Python ThreadingHTTPServer Thread-per-connection model exhausts OS threads and file descriptors beyond ~300 concurrent SSE streams. Asynchronous ASGI (FastAPI + Uvicorn workers) behind Traefik/Nginx with HTTP/2 multiplexing.
Vector Retrieval ChromaDB with global threading.RLock() All similarity searches are serialized; 100 QPS creates massive thread contention and latency spikes. Distributed vector cluster (Qdrant or PostgreSQL pgvector) with in-memory HNSW index.
LLM Inference Local CPU Ollama (qwen2.5:1.5b, 6 threads) CPU processes 1 generation stream sequentially (~20 tok/s). 2,500 users experience multi-hour queues. Continuous-batching GPU cluster (vLLM / TensorRT-LLM) or Azure OpenAI Provisioned Throughput.
State Database Single SQLite file (webui.db) SQLite locks on concurrent user writes, causing database is locked crashes. High-availability PostgreSQL cluster with PgBouncer connection pooling.
Audit Ledger Append-only flat file (aims_rag_audit.jsonl) File lock contention and disk I/O bottlenecks at 100+ audit writes per second. Clustered PostgreSQL or ClickHouse with immutable write-ahead logging (ISO 42001 Clause 7.5).

Path A: Enterprise Hybrid Cloud (Framework Reference Architecture)

Implements the Microsoft Cloud topology codified in the Master Implementation Handbook (Section 2):

  • Identity & Access: Microsoft Entra ID (Azure AD) SSO integration. User groups (Students, Faculty, Bursary, IT, Admin) map directly to Educore clearance tiers.
  • Frontend: Open WebUI deployed on Azure Container Apps with autoscaling (4 to 10 replicas) behind Azure Front Door.
  • Governance Layer: Stateless FastAPI middleware executing the 8 guardrails, Zambian NRC masking, and Purview container gating.
  • Retrieval & Purview: Azure AI Search (Standard S2 tier) indexing SharePoint Online libraries, natively enforcing Purview sensitivity labels.
  • Inference: Azure OpenAI Service deploying gpt-4o-mini (for universal RAG & Socratic tutoring) and gpt-4o (for executive/finance tasks) under Microsoft Enterprise Data Protection (zero customer data retention).

Path B: Sovereign On-Premises Private Cloud Cluster

Industrializes the current Python/Chroma/Open WebUI codebase into a sovereign Kubernetes cluster hosted in an Educore data center or Zambian tier-3 colocation facility:

  • Orchestration & Ingress: Kubernetes (k3s / RKE2) with Traefik Ingress, SSL termination, and rate limiting.
  • Frontend & Gateway: 6x Open WebUI replicas + 8x Educore Governance Gateway worker pods with Redis session caching.
  • Vector Database: 3-node Qdrant Distributed or PostgreSQL with pgvector cluster with HNSW in-memory indexing.
  • Inference Serving: 2x 8-GPU inference nodes running vLLM with PagedAttention and continuous batching over Llama 3.1 8B Instruct (FP8).
  • Audit Store: Clustered PostgreSQL or ClickHouse with immutable write-ahead logging.

Path C: Distributed Multi-Campus Hub-and-Spoke Architecture

Reflects Educore's geographical spread across Zambia (Sentinel Kabitaka, Sentinel Kalumbila, Trident College, Trident Preps, Frontier Nkisu):

  • Central Hub (Central Administration): Houses master corpus synchronization (FrameworkSyncService), global ISO 42001 audit ledger, Entra ID master directory, and high-tier executive models.
  • Campus Spokes (Local Edge Servers): Edge appliances (e.g. 2U servers with dual GPUs) deployed at each campus site. Serves local Open WebUI, local Socratic student tutoring, and local cached vectors with zero WAN latency.

4. Resource Requirements: 5,000 Users / 2,500 Concurrent

4.1 Concurrency & Workload Mathematical Modeling

In an educational and enterprise environment, 2,500 concurrent active users with open browser sessions exhibit the following load dynamics:

  • Human Query Cadence: Users type, read, and reflect, querying every 25 seconds on average.
  • Sustained Request Rate: 2,500 users / 25 seconds = 100 Queries per Second (QPS).
  • Peak Burst Factor (2.0x): 200 QPS during class start times or synchronized exam prep.
  • Simultaneous Active LLM Streams (Little's Law, L = λW): With an average generation duration of 4 seconds (~150–200 tokens):
    L(sustained) = 100 QPS * 4s = 400 simultaneous generating streams
    L(peak) = 200 QPS * 4s = 800 simultaneous generating streams

4.3 Network & Bandwidth Sizing

  • Streaming Egress Bandwidth: 400 active generation streams × 20 tokens/sec × 4 bytes/token ≈ 32 KB/sec raw payload. Including HTTP/2 SSE headers, TCP overhead, and WebUI polling: ~15 to 30 Mbps sustained egress.
  • Campus LAN: 1 Gbps switched backbone between access points and local gateways.
  • Campus WAN Uplink (Path A): Minimum 100 Mbps symmetrical dedicated fiber per campus with QoS prioritizing AI API endpoints.
